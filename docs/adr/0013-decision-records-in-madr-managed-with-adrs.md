# Decision records in MADR, managed with adrs

## Context and Problem Statement

The first twelve decision records were written in a format of our own: a
heading `# ADR NNNN: title`, a status and a date as bullets, and the sections
Context, Decision and Consequences. Their index, `docs/adr/README.md`, was
produced by a generator that we wrote and maintain, and nothing checked that a
record had the sections, a valid status or working links to other records.
That is tooling invented where an existing tool could do the job, against the
rule of [ADR-0006](0006-repository-and-toolchain.md).

Which format and which tool create, check and index the decision records?

## Decision Drivers

- No tooling invented where an existing tool does the job
  ([ADR-0006](0006-repository-and-toolchain.md)).
- The format of a record is checked automatically, not by convention.
- The index shows the status of each record.
- A new record keeps the four-digit number and the file name `NNNN-slug.md`.
- Plain Markdown that any reader and any agent can read, with no vendor syntax.

## Considered Options

- MADR 4.0.0, managed with `adrs` 0.13.0
- adr-tools
- log4brains
- adr-log
- Keep our own format and generator

## Decision Outcome

Chosen option: "MADR 4.0.0, managed with `adrs` 0.13.0", because it checks
the format of every record, validates the status, checks the links between
records and exports the records as data from which an index with status is
written, and it is an existing tool, not one of ours.

1. The records follow MADR 4.0.0 (<https://adr.github.io/madr/>): YAML front
   matter, the title as the only heading of level one, and the sections
   "Context and Problem Statement", "Decision Drivers", "Considered Options",
   "Decision Outcome" (with "Consequences", each prefixed Good, Bad or
   Neutral, and "Confirmation"), "Pros and Cons of the Options" and "More
   Information". The file name stays `NNNN-slug.md`.
2. The front matter has `number`, `title`, `status`, `date` and
   `decision-makers`. The decision makers are written as a role, `founder`,
   never as the name of a person. `number` and `title` are the two keys that
   `adrs` needs beyond plain MADR.
3. The tool is `adrs` (<https://github.com/joshrotenberg/adrs>), version
   0.13.0, installed by `mise` and pinned exactly in `mise.toml` and
   `mise.lock`. Its configuration is `adrs.toml` at the root: the directory
   `docs/adr`, front matter on, MADR templates, and `adrs doctor` with
   warnings as errors. Every key is written in the file and `ADRS_CONFIG`
   points at it, so that a user-level configuration cannot change a result.
4. `mise run adr:check` runs `adrs doctor` and is part of `mise run check`. It
   checks the sections, the status, the dates, the numbering and the links
   between records.
5. A reference from one record to another is a Markdown link, for example
   `[ADR-0010](0010-roles-and-access.md)`, so that the tool checks it. A
   reference from another file may stay "ADR 0010".
6. `docs/adr/README.md` is generated by `mise run generate`: the numbers,
   titles and statuses come from `adrs export json`, filtered with `jq`. The
   tool's own table of contents has no status, and it has no mode that fails
   when an index is stale; the small piece of glue that fills the gap is
   registered as GAP-023.
7. A new record is created with `adrs new "Title"` and filled in. The next
   free number is given by the tool.

### Consequences

- Good, because the format of every record is checked on every run of the
  checks: a missing section, an invalid status, a duplicate number or a broken
  link fails the check.
- Good, because the home-made index generator is replaced by the tool's
  export and a few lines of `jq`.
- Bad, because `adrs` is a version 0.x project with one maintainer
  (GAP-024). It is therefore pinned to an exact version, and an update is a
  deliberate change that runs `adr:check` and the index generation again.
- Bad, because the front matter has two keys beyond plain MADR, `number` and
  `title`, so a record is not plain MADR to another tool.
- Bad, because the tool does not require the section "Considered Options": a
  record without it passes, and one that lists fewer than two options only
  gets an informational message, which does not fail the check. That every
  record has the section, and lists no option that was never considered, is a
  rule of this ADR kept by review.
- Bad, because the tool checks only Markdown links between records: a plain
  "ADR 0010" is not checked, which is why the records use links.
- Bad, because the tool has no mode that fails on a stale index, so the glue
  that writes the index is ours (GAP-023).
- Neutral, because the status values are those of the tool: proposed,
  accepted, deprecated, superseded, rejected and draft.

### Confirmation

`mise run adr:check` fails when a record breaks the format the tool checks,
and `mise run generate:check`, which is part of `mise run check`, fails when
`docs/adr/README.md` is stale (R38, `test_R38_derived_files_generated`). The
decision of this record has no requirement of its own in the model. By hand,
on 2026-11-27, `adrs doctor` was seen to fail (exit status 1) on a record
that lacked the sections "Context and Problem Statement" and "Decision
Outcome", had an invalid status and linked to a record that does not exist; no
automated test repeats that check. The
sections and the content of the records beyond what the tool checks, such as
a "Considered Options" section in every record, are kept by review, not by a
test.

## Pros and Cons of the Options

### adr-tools

- Bad, because it has had no release since 2018.
- Bad, because its index has no status.
- Bad, because it does not check the format of a record.
- Bad, because a new record loses the four-digit number.

### log4brains

- Bad, because it was considered and not chosen; no reason was recorded.

### adr-log

- Bad, because it was considered and not chosen; no reason was recorded.

### Keep our own format and generator

- Bad, because it is tooling invented where an existing tool does the job
  ([ADR-0006](0006-repository-and-toolchain.md)), and we maintain the format,
  the generator and its check ourselves.

## More Information

- MADR 4.0.0: <https://adr.github.io/madr/>.
- `adrs`: <https://github.com/joshrotenberg/adrs>, configuration documented at
  <https://joshrotenberg.com/adrs/configuration.html>.
- The glue and the governance risk are registered in `gaps.toml` as GAP-023
  and GAP-024; both are to be proposed upstream or resolved by a change of
  tool.
- The records written before this one were converted to the new format; their
  content, decisions and rejected alternatives were moved as they were, and
  the rejected alternatives that the old text mentioned in passing now have a
  subsection under "Pros and Cons of the Options".
